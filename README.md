# OnePlus 13T / PKX110 (SM8750)

This community port uses UniXNU format 2: ARM64, the pinned SM8750 common repository, iPadOS 17.7.11 (21H461), and this device profile. The source drivers remain together in [UniXNU-Pagani-Drivers](https://github.com/IssacL04/UniXNU-Pagani-Drivers); `modules/Pagani` pins one commit. Community component metadata and recipes live in the maintained [main fork](https://github.com/IssacL04/UniXNU_Enc3l).

Builds 39 and 48 reached the iPadOS UI on a OnePlus 13T. UFS root reads and CPU framebuffer presentation were observed; build 48 later panicked on a UFS read timeout. Data is a volatile RAM seed. Basic touch response is user-confirmed in build 57, and power-key actions were confirmed in build 50. GPU acceleration, network, audio and complete power management remain unfinished. See [MIGRATION.md](MIGRATION.md) for the build-46 migration sources and checks, [porting.toml](porting.toml) for current scope and [STAGE6.md](STAGE6.md) for hardware observations.

The current source adds S3910 LBP touch, physical power/volume keys and DSI brightness/display blanking. [Actions build 48](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40183635568) passed the portable transport tests, original and compiled HID/backlight ABI checks, full kernel link and prelink. Touch currently polls ATTN and needs retained GENI microcode; presentation remains a 60 Hz software timer. See the input/display sections of [porting.toml](porting.toml) for limits.

[Build 49](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40327493773) included the UFS completion recheck. After a temporary boot, the user reported no repeat panic during the observed test, while touch, buttons and brightness remained unusable. The observation does not establish long-term stability.

[Build 59](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40483050380) enables all eight captured CPU affinities, preserves Aff2 for the Prime cluster, and installs the normal exception vectors on secondary CPUs after MMU setup. It excludes Apple-only CPU override registers and serializes console diagnostics. Touch logs are disabled by default; two CPU/RAM rows report registered/online counts and timer/IPI coverage. The owned RAM window stays at 4 GiB for this CPU trial. Full host checks, production object/ABI checks, kernel link and prelink passed in 21m38s. The downloaded `out/oneplus13t/actions/run-59/kernel/kernel.macho` is 127,803,392 bytes; its hash, all source pins, eight-core arguments, platform strings and paired RAM Data integrity/UUID pass local checks. The matching `out/oneplus13t/boot/stage7-run-59/boot.img` is 87,957,504 bytes and passes Android/FAT readback, all eight ADT affinities, PSCI and same-build kernel/trust/Data checks. At the user's request, fastboot accepted its temporary launch: Sending and Booting returned OKAY in 2.680s without flashing a partition. The user then reported a kernel panic. Its lock address resolves to the scheduler pset0 lock on CPU affinity 0x200; no eight-core online or UI qualification was obtained.

[Build 60](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40499765573) keeps the same CPU policy and adds logical CPU/compact thread IDs, ticket state and up to eight return addresses to this panic. Full checks, object/ABI validation and kernel link/prelink passed in 11m49s. The diagnostic kernel and paired inputs are downloaded and verified at `out/oneplus13t/actions/run-60/`. The matching `out/oneplus13t/boot/stage7-run-60/boot.img` passed Android/FAT/ADT and same-build input readback. At the user's request, fastboot Sending and Booting both returned OKAY in 2.659s without flashing a partition. The user then captured another panic: CPU 2, equal current/owner IDs and a return path through thread_select() after Clutch steal. The selected Clutch callback is a single-cluster stub that leaves its caller holding the pset lock. Creating a second pset exposes a recursive acquisition. The next candidate uses the existing single-pset policy for all eight CPUs while retaining both hardware clusters; the source regression reproduces the old failure and passes with the policy correction.

[Build 62](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40505777459) passed all host/production contracts, original and compiled ABI checks, kernel link and prelink in 21m29s. The downloaded kernel and matching inputs are verified at `out/oneplus13t/actions/run-62/`. The actual linked Clutch table has the single-pset policy, with all eight CPU affinities retained. The matching `out/oneplus13t/boot/stage7-run-62/boot.img` passed Android/FAT/ADT and same-build input readback. At the user's request, fastboot Sending and Booting both returned OKAY in 2.671s without flashing a partition. The user then reported a panic at display slot 345, caller 0xfffffff00578c1cc. The pinned original code reaches this boolean TimingEnable query after a five-second swap wait timeout. A deterministic host regression reproduces a lost display handoff under console-lock contention; the candidate waits for the current writer, still exits immediately on panic, and supplies the qualified logical timing query.

[Build 63](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40520726310) passed all host/production contracts, the exact original and compiled 358-slot display ABI checks, and kernel link/prelink in 17m00s. The downloaded kernel and matching inputs at `out/oneplus13t/actions/run-63/` pass local integrity and source-pin checks. The final display vtable points slot 345 to the logical timing implementation, the handoff retry is compiled into the kernel, and the Clutch single-pset policy remains active. The matching `out/oneplus13t/boot/stage7-run-63/boot.img` passed Android/FAT/ADT and same-build input readback. At the user's request, fastboot Sending and Booting both returned OKAY in 2.791s without flashing a partition. System startup, eight-core online counts and sustained UI/touch interaction await observation. Memory expansion can start with a separate 5 GiB request; the captured Android map contains a contiguous 9 GiB range, but larger windows require the actual UEFI free map and matching DRAM declarations.

[Build 57](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40461298553) publishes a standalone touchscreen identity and a product/SPI-scoped event-driver personality. Reports wait for qualified binding and collection dispatch; an instance-local, ABI-checked dispatch wrapper adds edge-origin flags and exposes actual event counts and coordinates. Host regressions, production compilation, original/compiled ABI checks and full kernel link/prelink passed in 17m11s. The kernel at `out/oneplus13t/actions/run-57/kernel/kernel.macho` is 127,803,392 bytes; source pins, diagnostic strings and paired RAM Data integrity/UUID passed local checks. The matching image at `out/oneplus13t/boot/stage7-run-57/boot.img` (87,957,504 bytes) passed Android/FAT readback and was temporarily booted at the user's request. Fastboot Sending and Booting returned OKAY without flashing a partition. The user subsequently confirmed that touch is working. This records basic touch response in the observed session; multi-touch, coordinate calibration, system edge gestures and long-term stability still need specific validation.

[Build 56](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40448445357) adds explicit RPMh requests for the 13T touch rails (1800/3100 mV), a 200 ms power wait, and checked SPI CS/word delays of 50/0. Resource identity, idle-slot ownership, register readback and all command acknowledgements are required before reset. Host regressions, production object/ABI checks and full kernel link/prelink passed. The downloaded kernel is at `out/oneplus13t/actions/run-56/kernel/kernel.macho` (127,799,296 bytes); its hash, source pins, diagnostic strings and paired RAM Data integrity/UUID passed local checks. The matching image at `out/oneplus13t/boot/stage7-run-56/boot.img` (87,953,408 bytes) passed local assembly and readback. After the user connected fastboot, Sending and Booting both returned OKAY for a temporary boot, without flashing a partition. Hardware feedback now confirms a valid TouchComm v1 identification header, changing contact masks and successful kernel HID report submissions. Swipes do not move the lock screen and tapping Cancel in the power menu does not respond. UI touch delivery and coordinates remain unqualified; the next investigation targets touchscreen identity, event-driver attachment and dispatch.

The previous tested image is [Actions build 55](https://github.com/IssacL04/UniXNU-Pagani_SM8750/actions/runs/40437346840). Build 54 returned success from its first SPI read, then rejected four zero header bytes with `TOUCH T0 00 header r=ffffffb9 v=0 n=0` before touch HID startup. Build 55 retains the first successful read in two existing rows: `SPI RX` shows the bytes and ATTN/RESET levels, and `SPI dma` shows the transfer counters and GENI state. Transport mode, reset timing and protocol checks are unchanged.

Portable regressions, original and compiled HID/backlight ABI checks, the early-console runtime check, full kernel link/prelink and local image readback passed. The kernel is at `out/oneplus13t/actions/run-55/kernel/kernel.macho` (127,799,296 bytes), and the complete Android v4 image is at `out/oneplus13t/boot/stage7-run-55/boot.img` (87,953,408 bytes). It was sent with `fastboot boot`; Sending and Booting returned `OKAY`, without flashing a partition. The user confirmed no touch response: `SPI RX n=4 h=00000000 a=0/0 rst=3` and `SPI dma=1 ti=4 ri=4 st=0`, with `TOUCH T0 00 header r=ffffffb9 v=0 n=0`. The first four-byte SE DMA read completed but yielded a zero header. These values do not qualify sensor communication or its power rails. A read-only Android baseline confirms the OnePlus driver enables 1.8 V and 3.1 V touch rails and logs valid `a5` frames with `cs_clk_delay=50`; build 55 did not explicitly program that delay. The later build-56 runtime results are recorded above. Earlier images are preserved. See [STAGE6.md](STAGE6.md) for exact revisions and checks.

On build 50, the phone reached the lock screen; short power presses switch the screen off/on and a long press opens the shutdown UI. Volume presses advance the key-report counter. Touch failed at TouchComm startup with no reports. That observation does not yet establish which protocol mismatch caused the failure; build 51 tests the compatibility fixes above. Brightness remains unqualified.

## Workspace and inputs

Keep `UniXNU/`, `UniXNU-Pagani_SM8750/`, `UniXNU-Pagani-Drivers/`, `UniXNU-sm8750-common/` and `UEFI-Pagani_SM8750/` as sibling checkouts. `upstream.rev` pins the maintained main fork used by CI. Read [AGENTS.md](AGENTS.md) and the [migration guide](https://unixnu.com/porting/migration).

Run from **UniXNU**, using `unixnu.local.toml` for private paths. Set `build.device`, `uefi`, `edk2`, the full stock firmware DTB, the decompressed 21H461 kernelcache, a nonzero private platform seed, the verified trust-cache bundle and the prepared RAM Data image. Input provenance is in [proprietary-files.txt](proprietary-files.txt). Optional source-development overrides are in [local.toml.example](local.toml.example); published builds use the committed gitlink, feed and lock.

```sh
./unixnu defconfig oneplus13t_defconfig -D ../UniXNU-Pagani_SM8750
./unixnu fetch
./unixnu status --json
./unixnu tree
./unixnu ipsw fetch AppleLogo KernelCache OS Cryptex1,SystemOS StaticTrustCache Cryptex1,SystemTrustCache
```

The output directory is `out/oneplus13t/ipados-17.7.11-21H461/oneplus13t/`. Before the kernel build, prepare the root-window policies, original trust bundle and volatile Data seed as shown in [.github/workflows/xnu.yml](.github/workflows/xnu.yml). The seed preparation requires macOS. The Linux kernel toolchain is not provisioned by this repository; see the main [host requirements](https://unixnu.com/guide/requirements).

```sh
./unixnu kernel
./unixnu build package
./unixnu firmware
./unixnu payload
./unixnu bootimg
```

The firmware contains both standard `UniXNURamDiskDxe` and the 13T `BootPayloadDxe` embedded-payload handoff. Keep `bootimg.embed_payload = true`: the stock ABL uses `init_boot`'s ramdisk during temporary boot. `dts/oneplus13t.dts` describes XNU hardware; it does not replace the separate stock DTB used to package the Android boot image.

The physical root target is the existing 64 GiB **unixnu** partition, LUN 0, LBA 44928768 through 61705983 at 4096 bytes per block. Runtime physical writes remain disabled. `userdata-root.img` is a historical filename, not permission to overwrite Android `userdata`. This migration does not perform device writes or boots.
